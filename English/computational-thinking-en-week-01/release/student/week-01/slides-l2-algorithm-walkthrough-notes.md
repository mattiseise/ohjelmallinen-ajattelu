## Slide 1 — Worked example — instant noodles

Frame this as a slow walk through one familiar task using the four parts of an algorithm from Slide 9 of the main deck. The point is not that anyone needs help making noodles — it is that the same skeleton (goal · input · steps · output) holds up under any task they will meet later in the course. Tell the class: if you can name these four parts for noodles, you can name them for a help-desk reply, a backup script, or a route across town. Ask: "What was the last thing you cooked or assembled?" Hold that example in mind as we walk the slides. ~2 min.

## Slide 2 — Goal

The goal is the destination — what is true at the end. Make students notice it is a noun phrase, not a verb: "a bowl of hot noodles, ready to eat", not "make noodles". A clear goal lets a literal follower know when they are done. Concrete IT version: "a recoverable backup of the project folder on the external drive" — a noun phrase, ready to be checked. Ask: "How would you know you had reached this goal? What would you see?" That answer is the test. ~3 min.

## Slide 3 — Input

The input is everything the follower needs before they can start. If the input is incomplete, the algorithm cannot run — they will stop and ask. Walk the bullets and have students notice each one is concrete, named, and countable. No "some bread" or "a bit of water". Concrete IT version: to reset a password, the input is the user's account name, the admin tool URL, and the temporary password format. Ask: "What goes wrong if we forget to list the bowl in the input?" The follower has nowhere to pour. ~3 min.

## Slide 4 — Steps

Six steps, in order, each a single action a literal follower can do without guessing. Read them out and tap two details: "fill the kettle to the line on the side" (no guessing about quantity) and "wait until it clicks off" (no guessing about time). Compare those to a sloppier version — "boil some water" — to show what we are avoiding. Concrete IT version: each step in a backup script is one verb plus one named thing. Ask: "Pick one of these steps. What would happen if a follower did it slightly wrong?" That is where edge cases hide. ~5 min.

## Slide 5 — Output

The output is what the follower actually has at the end. Notice it should match the goal — if not, something in the steps is off. Drawing this match-up is how students will later test their own algorithms in pairs. Concrete IT version: the output of the backup script is a dated folder on the external drive. If the drive is empty when the script finishes, the steps did not deliver the goal. Ask: "If the output and the goal do not match, where do you look first?" Answer: the steps. ~3 min.

## Slide 6 — The template scales

Land the closing point: this same four-part shape carries every algorithm in the course. A morning routine, a help-desk reply, a backup script, a bus route. Naming the four parts makes the algorithm easier to test (does the output match the goal?), easier to share (someone else can pick it up), and easier to fix (you know which part to look at). Ask the class: "Name one algorithm from your week. Tell me its goal in one noun phrase." Pick two volunteers. That is the assignment now baked in. ~3 min.
